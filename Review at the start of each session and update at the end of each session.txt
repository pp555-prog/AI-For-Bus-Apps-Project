   │   ├── bookings.py      POST /api/bookings, GET /api/bookings
   │   ├── ai.py            POST /api/ai/vibe-match, /generate-bio,
   │   │                        /promo-prompt, /party-simulation
   │   └── radar.py         GET /api/radar — live booking feed with time_ago
   └── services/
       ├── claude_client.py Anthropic SDK wrapper (model: claude-sonnet-4-20250514)
       ├── vibe_matcher.py  Builds DJ catalog prompt → Claude → JSON scores + reasoning
       └── higgsfield.py    Claude-generated Higgsfield video prompts for party sims

5. Wired all 4 UI pages to the API via <script> tags:
   - discovery.html  → fetches /api/djs, /api/venues, /api/radar
   - search.html     → POST /api/ai/vibe-match on textarea submit; GET /api/djs with filters
   - vibe-search.html → reads ?dj= URL param → GET /api/djs/{id}; populates all fields
   - booking.html    → reads ?dj= URL param; form submit → POST /api/bookings

6. Created Procfile for Render deployment:
   web: uvicorn backend.main:app --host 0.0.0.0 --port $PORT

7. Pushed all 28 files in initial commit to GitHub.

KEY DECISIONS
-------------
- SQLite + aiosqlite (no ORM, no Postgres) — right for a class project MVP
- No auth — skipped for v1
- Static mount AFTER API routers so /api/* always wins
- Claude model: claude-sonnet-4-20250514 (speed + cost balance)
- Vibe matcher returns structured JSON: {query_interpretation, matches: [{dj_id, score, reasoning}]}
- JSON fields (genres, vibe_keywords, tech_rider, availability) stored as TEXT in SQLite,
  parsed by Pydantic @field_validator on read
- Image URLs for DJs/venues point to external CDN URLs embedded in the original HTML

- No authentication, no payment processing — intentionally out of scope for MVP
