# Claude Instructions

**Read [`AGENTS.md`](./AGENTS.md) first.** It is the canonical onboarding document for this project and applies to all AI agents, including Claude.

This file exists only to ensure Claude Code (which auto-loads `CLAUDE.md` at session start) reaches `AGENTS.md`.

## Claude-Specific Notes

- **Session log:** the canonical session log is `Review at the start of each session and update at the end of each session.txt` in the project root. Read it before doing any work; append a new `SESSION N` block at the end of every session.
- **Worktrees:** when working in a `.claude/worktrees/*` checkout, treat the file in the **main project root** as the source of truth for `SPEC.docx`, `README.md`, `AGENTS.md`, `CLAUDE.md`, and the session log. Always copy edits back to the main project root before finishing — Word and other tools open the main copy, not the worktree.
- **LLM provider:** as of SESSION 18, the runtime LLM is routed through OpenRouter (OpenAI SDK pointed at `https://openrouter.ai/api/v1`). The active model is set by `OPENROUTER_MODEL` in `.env` (default `openai/gpt-oss-120b:free`). Don't reintroduce the `anthropic` SDK or hard-code Claude — use `from backend.services.llm_client import complete` and let `OPENROUTER_MODEL` decide.

- **Personalized class demo:** as of SESSION 22, `/personal-demo.html` is the main demo path for uploading Pablo's performer photos, matching him to a venue, and submitting/polling an OpenRouter video job. Default video model is `bytedance/seedance-2.0` via `backend/services/openrouter_video_client.py`. Do not reintroduce fal.ai or Higgsfield as the live video provider unless the user explicitly asks.
- **Live music generation:** the demo also fires a Google Lyria 3 clip per matched venue via `backend/services/lyria_client.py` (`google/lyria-3-clip-preview`, routed through the same OpenRouter key). Don't reintroduce Suno as a runtime provider — there is no official Suno public API and the project explicitly chose Lyria for the single-key OpenRouter architecture.
- **Lyria requires streaming + modalities:** to actually receive audio (not just a text caption), the chat-completions request MUST include `modalities: ["text","audio"]` AND `stream: true`. Audio comes back as one or more `delta.audio.data` base64 chunks inside the SSE stream. Do not use httpx's `aiter_lines()` for the response — Lyria's audio chunk is a single ~1 MB SSE event whose `data:` line some httpx versions fragment incorrectly. Parse `aiter_bytes()` and split on `\n\n` instead (see `lyria_client.py` for the working pattern).
- **Seedance audio is disabled:** `openrouter_video_client.py` sends `generate_audio: false`. ByteDance's content-safety filter rejected our test job at 137s with `"output audio may contain sensitive information"` when audio was on. Lyria already produces the music; the demo syncs Lyria/fallback audio with the silent Seedance video and can call `/api/ai/demo-performance-video/mux` to bake the soundtrack into the MP4 when ffmpeg is available through `FFMPEG_PATH`. Don't flip Seedance audio back to `true` without verifying the safety filter has changed — a failed run wastes ~$1.50 and ~2 minutes of demo time.
- **Seedance refuses real-person photos:** as of 2026-04-29, performer photos are blocked at submit time by ByteDance's `"InputImageSensitiveContentDetected.PrivacyInformation"` policy (same on Veo 3.1 and Sora 2). `backend/routers/ai.py demo_performance_video` sends ONLY the venue's `image_url` as `input_references` — performer photos are uploaded by the frontend but intentionally NOT forwarded. Don't re-enable performer-photo references without verifying the policy has lifted (it hasn't on any of the three major providers).
- **OpenRouter video data-URL size limit:** payloads above ~2 MB silently fail (200 OK with `id: null`). The §9.6 eval (`evals/seedance_video_eval.py`) auto-resizes photos to ≤1024 px JPEG via Pillow before encoding. Pillow is in `requirements.txt`. Mirror the same resize step in any future image-conditioned video call.
- **Seedance prompt is Multi-Shot, not Single-Shot:** as of 2026-04-30 `build_seedance_prompt()` produces a 10-second three-beat afterparty arc (Establish → Develop → Payoff) per the Seedance 2.0 AI Handbook page 8, not a single continuous shot. Each beat has its own dominant camera move; transitions are crossfades. Don't collapse it back to a single shot — single-angle DJ shots felt visually inert in the §9.6 eval and the multi-shot variant is what we're shipping. The §9.5 linter accepts either mode; it auto-detects via the presence of `Beat 1`/`Beat 2`/`Beat 3` markers.
- **Audio-input style analysis:** when a user uploads a track on `/personal-demo.html`, the frontend trims it client-side to 30s mono 16 kHz WAV and posts it to `/api/ai/demo-venue-match`. The backend runs `backend/services/audio_analyzer.py` (default `google/gemini-2.5-flash` via OpenRouter chat-completions with `input_audio` content blocks). The structured analysis is concatenated with the user's typed style and fed to the LLM venue matcher (`vibe_matcher.match_venues`). Don't add a server-side audio decoder — keep the trim on the frontend so we don't pull in pydub/ffmpeg.
